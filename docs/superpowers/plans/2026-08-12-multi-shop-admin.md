# 多 Shopify 店铺订单后台实施计划

日期：2026-08-12

## 目标

将当前由 `ADMIN_SHOP` 固定到单一店铺的独立订单后台改造成安全的多店后台。工作人员登录一次后，可以从服务器已配置的 Shopify 店铺白名单中选择一个店铺，查询该店铺的定制订单并下载对应生产 ZIP。

## 阶段 1：配置与接口契约

- 从 `SHOPIFY_STORE_CONFIG_JSON` 的店铺键生成只读 `adminShops` 白名单。
- 保留 `ADMIN_SHOP` 作为默认店铺和现有登录会话签名范围，兼容当前部署。
- 会话接口返回默认店铺和完整白名单。
- 订单查询和下载接口接受 `shop` 参数，并拒绝白名单之外的域名。

不做：不改变 Shopify webhook、报价签名、数据库 schema 或管理员密码模型。

验证标准：未知店铺、大小写变体和跨店下载均失败；合法店铺只读取本店数据。

## 阶段 2：后台店铺选择器

- 在筛选区域增加 Shopify 店铺下拉选择器。
- 切换店铺时重置分页并重新查询。
- 下载链接显式携带当前店铺，服务端再次校验白名单。
- 保持现有桌面和移动端视觉风格。

不做：不提供“全部店铺”混合查询，不新增管理员账号或角色系统。

验证标准：登录后默认选中 `ADMIN_SHOP`；可以切换到其他配置店铺；查询、分页和下载始终使用当前店铺。

## 阶段 3：本地验收与部署准备

- 运行配置、后台门户、运行时集成测试及完整测试。
- 在本地真实启动后台，检查登录、店铺切换、空状态、订单状态和响应式布局。
- 更新变更日志和腾讯云部署说明。
- 输出服务器备份、私有配置修改、容器重启、验证和回滚步骤。

不做：未经单独确认，不修改腾讯云 `.env.server`、不重启容器、不更新 Shopify App 权限、不创建新订单。

## 风险与控制

- **跨店数据泄露：高风险。** 所有客户端 `shop` 值必须由服务端白名单校验，数据库查询和下载继续强制包含 `shop` 条件。
- **旧会话兼容：中风险。** 保留现有 `ADMIN_SHOP` 会话签名方式，部署后不要求更换后台密码；如配置改变导致旧会话失效，重新登录即可。
- **配置错误：中风险。** 默认店铺必须仍存在于店铺配置中，所有白名单键必须是规范的小写 `*.myshopify.com`。
- **既有订单无法补投：中风险。** 多店后台只解决可见性和隔离；未订阅 webhook 时产生的旧订单不会由本功能伪造或补写。

## 回滚点

- 本地：恢复本计划涉及的服务器后台文件即可；无数据库 migration。
- 腾讯云：部署前备份当前镜像、`.env.server`、SQLite 和对象目录；失败时恢复旧镜像及旧配置并重启，保留数据目录。
