# Shopify 3D 球衣 App 与生产文件工作流设计

日期：2026-07-30
状态：用户已确认设计，等待实施计划
首发范围：当前单一 Shopify 店铺，稳定后再验证多店安装

## 1. 目标

将现有 3D 球衣定制器逐步改造成可在 Shopify 中稳定运行的 App，并完成以下闭环：

1. 顾客不依赖本地开发环境即可打开和使用 3D 定制器；
2. 顾客只能选中摄像机真实可见、未被衣服遮挡的元素；
3. 文字、号码和图片只显示在球衣模型外侧；
4. 顾客界面不显示连续底纹的高级参数；
5. 加入购物车前将完整设计和生产文件暂存到云端；
6. Shopify 支付成功后，将设计与订单关联并生成正式生产单；
7. 工作人员可以从 Shopify 订单详情或 App 定制订单列表下载生产文件；
8. 商家可以在 App 后台上传或替换 GLB 模型并配置模型参数；
9. 当前先输出 UV 参考 PDF，拿到工厂 1:1 裁片模板后再扩展为真实生产 PDF。

## 2. 非目标

首发阶段不包含：

- 类似 Blender 的网格、领口、袖子或拓扑编辑；
- Shopify App Store 上架、订阅计费或多租户运营；
- 浏览器直接生成原生 CDR；
- 在没有工厂真实裁片尺寸时伪造 1:1 生产文件；
- 自动修改库存、履约或第三方工厂系统；
- 把未付款购物车草稿直接交给工厂生产。

## 3. 现有基础与已知限制

现有项目已经具备：

- React + Three.js 3D 定制器；
- Cloudflare Worker；
- Shopify App Proxy 加购交接；
- 服务端可信报价、Cart Transform 与 Checkout Validation；
- `designId`、`bundleId`、签名合同和设计记录；
- Shopify 购物车私有属性 `_jersey_design_id`；
- 本地 `design.json`、部分 UV Atlas 与生产 ZIP 能力；
- 正面、背面视角和个性化元素正背面数据；
- Shopify 商品页启动入口。

现有实现尚缺少：

- R2 云端生产文件存储；
- 可按订单查询的持久化索引；
- `orders/paid` 订单关联流程；
- Shopify 后台生产文件卡片和定制订单列表；
- App 后台模型管理；
- 包含模板、文字、号码和图片的完整 UV 烘焙；
- UV 参考 PDF；
- Theme App Extension / App Block 的正式入口；
- 新模型发布前的法线、UV 和正背面验证。

环境限制：

- 项目记录表明 `testcsj.myshopify.com` 是 client-transfer 店铺；
- 该店可继续用于主题与前端预览，但不应作为最终自定义 App 与 Shopify Functions 的正式联调环境；
- App 和订单闭环联调需要 app-development 店铺，或最终可安装已发布 App 的商家店。

## 4. 选择的实施方式

采用分阶段演进，不一次性重写。

原因：

- 现有 Worker、App Proxy、Functions 与签名报价可以复用；
- 3D 交互、文件导出、云存储和订单后台是不同风险域；
- 每阶段可以独立测试、部署和回退；
- 先解决当前顾客可见问题，再逐步扩展生产与后台能力。

未选择的方案：

- 一次性完成全部 App 化：改动面过大，问题难以隔离；
- 只修当前页面：无法解决生产文件、本地依赖和订单取件问题。

## 5. 顾客端界面简化

### 5.1 连续底纹高级参数

顾客界面移除整块 `BottomPatternPanel`，不再显示：

- Enable continuous bottom pattern；
- Pattern preset；
- Pattern scale；
- Pattern rotation；
- Horizontal repeat；
- Vertical repeat；
- Reset controls。

当前默认底纹状态已经是：

```text
enabled = false
source = none
```

因此新设计继续使用默认关闭状态。

底层底纹配置、设计文件读取和渲染兼容代码暂时保留，避免破坏历史设计文件或未来后台能力。现有 `Gradient / Color Block`、分区颜色、文字、号码和图片不受影响。

## 6. 摄像机可见元素选择

### 6.1 已确认交互

采用“摄像机真实可见性”，不采用严格正面/背面模式锁定。

- 正面视角不能选中被衣服遮挡的背面元素；
- 背面视角不能选中被衣服遮挡的正面元素；
- 45° 或侧面视角可以操作实际露出的元素；
- 判断不依赖用户是否点击了 Front / Back 按钮；
- 文字、号码、预设图片和上传图片使用同一套规则。

### 6.2 当前根因

当前文字和号码点击流程只对所有 `printLayers` 的平面做射线检测，没有把元素命中距离与衣服表面的命中距离比较。元素平面还使用 `THREE.DoubleSide`，所以摄像机可以从反面命中它。

当前图片点击流程只对 `DecorationEditor` 的所有图片表面做射线检测，同样没有统一的衣服遮挡判断，图片材质也使用 `THREE.DoubleSide`。

渲染深度测试只决定像素是否显示，不会自动阻止 Three.js Raycaster 命中被遮挡的对象。因此仅依赖 `depthTest` 不能解决串选问题。

### 6.3 统一选择规则

为文字、号码和图片建立共享的可见性判断：

1. 使用当前摄像机和指针生成一条射线；
2. 获取元素候选命中；
3. 获取同一条射线对球衣可打印网格的最近命中；
4. 将候选元素表面法线转换到世界坐标；
5. 只保留位于摄像机视锥内、法线朝向摄像机的候选；
6. 如果衣服命中比元素命中更靠近摄像机，且距离差超过表面容差，则拒绝该元素；
7. 对剩余候选按距离排序，选中最近元素。

表面容差只用于处理贴花位于衣服表面外侧的微小偏移，不能大到允许射线穿过衣服。

### 6.4 拖动规则

- 拖动射线只接受法线朝向摄像机的外侧衣服命中；
- 不允许从当前可见表面穿过衣服跳到另一面；
- 拖动结束时再次执行表面、方向和完整覆盖验证；
- 如果最终位置无效，恢复到该元素最后一个有效状态，不写入伪成功位置；
- 正背面切换仍通过现有明确操作完成，不支持直接拖过球衣边缘自动换面。

## 7. 元素只显示在模型外侧

### 7.1 当前根因

当前文字/号码拖动平面、个性化贴花、图片平面和图片贴花都存在 `THREE.DoubleSide`。

文字和号码的贴花几何已经具备按目标法线过滤三角面的逻辑，但材质仍是双面；图片贴花还没有使用同等级的外向三角面过滤。结果是从领口、袖口或模型内部观察时，外部图案可能从背面被渲染出来。

### 7.2 渲染规则

- 元素拖动平面和最终贴花材质使用 `THREE.FrontSide`；
- 文字、号码和图片贴花统一过滤与目标外向法线不一致的三角面；
- 默认放置射线从对应区域外侧向模型发射，并验证命中法线方向；
- 图片贴花复用个性化贴花的外向几何规则，避免维护两套不同判断；
- 不直接把球衣基础材质统一改成单面，除非真实模型验证表明这样不会破坏领口、袖口或内衬显示；
- 模型外侧判断以网格法线和模型配置为基础，不使用“离模型中心更远”作为唯一依据。

### 7.3 新模型验证

后台上传 GLB 后必须检查：

- 文件可以解析，且大小、类型和结构符合限制；
- 配置的球衣网格存在；
- 可打印网格有 UV；
- 正面、背面和外向法线方向与模型配置一致；
- 默认正面、背面放置射线能命中正确表面；
- 文字、号码和图片在正面、背面、45°、领口和袖口视角通过外侧显示测试；
- 不支持的变形网格或骨骼结构被明确拒绝或标记为不兼容。

验证失败时阻止发布模型版本，并在后台显示具体原因。不得重新启用双面元素渲染来掩盖模型问题。

## 8. 完整 UV 与 PDF 输出

### 8.1 当前能力差距

当前 UV Atlas 主要服务连续底纹烘焙，并不是包含所有顾客图案的完整生产 UV。新导出器必须把以下内容合成到模型 UV：

- 模板和分区颜色；
- 文字；
- 球员姓名与号码；
- 预设图片；
- 顾客上传图片；
- 未来恢复的底纹或其他可打印图层。

### 8.2 第一版生产包

每个设计生成：

```text
order-<order-number>-design-<short-id>.zip
├── design.json
├── uv-atlas.png
├── uv-reference.pdf
├── preview-front.png
├── preview-back.png
└── manifest.json
```

文件职责：

- `design.json`：可重新编辑的语义设计数据；
- `uv-atlas.png`：完整 UV 图案，第一版默认 4096 × 4096，允许模型配置覆盖；
- `uv-reference.pdf`：UV 图案参考页，包含订单、商品、尺码、模型版本、分辨率和颜色信息；
- `preview-front.png` / `preview-back.png`：生产人员快速核对；
- `manifest.json`：文件名、字节数、SHA-256、设计版本、模型版本、UV 版本和生成时间。

生产 ZIP 必须按 manifest 验证完整性后才标记为可下载。

### 8.3 PDF 与 CDR

第一版输出 UV 参考 PDF，不声称它是工厂 1:1 裁片稿。

原因：

- 模型 UV 是归一化展开坐标，不包含真实厘米尺寸；
- 模型 UV 不包含缝份、出血、裁片编号和尺码放码；
- 浏览器或服务端不应直接生成无法可靠验证的原生 CDR。

CorelDRAW 可以导入 PDF；如工厂需要 CDR，可先在 CorelDRAW 中打开 PDF 后另存。

未来拿到工厂的 CDR、PDF、AI 或 DXF 真实裁片模板后，为对应模型新增生产模板映射：

```text
完整设计数据 + 模型 UV + 工厂 1:1 裁片模板
→ 裁片映射器
→ 带真实尺寸、出血与裁片编号的生产 PDF
```

该扩展只新增模型生产模板与导出适配器，不重做 3D 编辑器、订单关联或云端文件生命周期。

## 9. 云端数据与文件架构

### 9.1 存储职责

使用：

- Cloudflare R2：GLB、纹理、UV PNG、PDF、预览图、JSON、manifest 和 ZIP；
- 现有 KV：短期签名报价和加购交接数据；
- Cloudflare D1：可搜索的设计、订单、文件索引、模型版本与生产状态；
- Cloudflare Worker：上传、校验、签名、报价、App Proxy、订单回调和安全下载。

不使用 KV 承担需要按订单号筛选、分页和状态更新的后台订单列表。

### 9.2 逻辑记录

设计/订单索引至少包含：

```text
shop
design_id
bundle_id
shopify_order_gid
shopify_order_name
status
product_id
variant_id
size
model_id
model_version
manifest_key
created_at
paid_at
updated_at
```

文件对象使用不可预测的内部键保存。后台与顾客均不直接看到 R2 路径。

### 9.3 状态

```text
designing
→ cart_draft
→ paid_pending_production
→ in_production
→ completed
```

异常或业务状态：

```text
file_error
cancelled
refunded
archived
```

规则：

- `cart_draft` 默认保留 30 天；
- 已付款订单第一版不自动删除；
- 已完成订单仍可从后台下载；
- 取消或退款只更新状态，不立即删除文件；
- 后续根据实际运营和隐私政策再确定已付款文件保留年限。

## 10. 加购与支付后的订单关联

### 10.1 加入购物车之前

顾客点击加入购物车时：

1. 读取稳定的设计状态快照；
2. 生成完整 UV、前后预览和设计 JSON；
3. 上传源文件；
4. Worker 校验文件类型、大小、哈希和设计结构；
5. Worker 生成 PDF、manifest 与生产 ZIP；
6. 文件和索引全部写入成功后生成/确认 `designId`；
7. 继续使用现有可信报价和签名合同；
8. App Proxy 将商品与私有 `designId` 属性加入 Shopify 购物车。

任一文件失败时不跳转购物车，保留当前设计并显示可重试错误。

### 10.2 支付成功

生产单只由 `orders/paid` 触发，不由 `orders/create` 触发。

订单回调处理：

1. 使用原始请求体验证 Shopify HMAC；
2. 验证回调店铺和主题；
3. 从订单商品行读取 `_jersey_design_id`、bundle 标识和签名信息；
4. 验证设计记录、报价、订单商品和生产文件 manifest；
5. 使用 `(shop, order_gid, design_id)` 唯一约束实现幂等；
6. 将设计关联到 Shopify 订单；
7. 锁定模型与文件版本；
8. 状态更新为 `paid_pending_production`；
9. 缺少或损坏文件时更新为 `file_error`，不得显示为待生产。

退款和取消回调用于更新状态，但不自动删除文件。

## 11. Shopify App 界面

### 11.1 顾客商品页

使用 Theme App Extension / App Block 代替长期依赖 Horizon DOM 结构的启动脚本。

App Block：

- 绑定当前 Shopify 商品和变体；
- 打开云端 3D 定制器；
- 传递最小必要的商品上下文；
- 不在前端暴露签名密钥、R2 路径或管理员配置。

### 11.2 Shopify 订单详情入口

订单详情显示一个 Admin Block：

- 设计前后预览；
- 设计状态；
- 商品、尺码和模型版本；
- 下载生产 ZIP；
- 分别下载 PDF、UV PNG 和 JSON；
- 打开 App 中的完整生产单；
- 文件异常时显示明确错误，不显示伪下载按钮。

### 11.3 App 定制订单列表

提供：

- 按 Shopify 订单号、`designId` 和状态搜索；
- 待生产、生产中、已完成、异常、退款等筛选；
- 单个或后续批量下载；
- 修改生产状态；
- 查看模型版本和 manifest；
- 从订单列表返回 Shopify 订单。

工作人员不需要记 R2 路径或手动匹配文件名。

### 11.4 模型管理

第一版后台模型能力：

- 上传或替换 GLB 与纹理；
- 将模型绑定到商品；
- 配置球衣网格、默认正背面视角、正面方向、UV 输出分辨率和生产模板版本；
- 执行模型兼容性检查；
- 预览通过后发布新版本；
- 查看旧版本，但不覆盖旧订单引用。

不提供网格顶点或拓扑编辑。

## 12. 错误处理与安全

### 12.1 文件

- 校验扩展名、MIME、文件魔数、大小和像素尺寸；
- 顾客上传图片限制为明确允许的格式；
- 生成 PDF 与 ZIP 时不使用顾客提供的路径；
- 文件名由服务端生成并清理；
- 每个文件记录 SHA-256；
- R2 bucket 保持私有；
- 下载由已登录 Shopify 管理员授权，并生成短期链接；
- 过期链接不能继续下载。

### 12.2 回调与幂等

- 所有 Shopify 回调验证 HMAC；
- 回调处理允许安全重试；
- 同一订单和设计只能生成一个正式生产记录；
- 部分写入失败必须回滚逻辑状态或标记明确异常；
- 不吞掉上传、PDF、ZIP、R2、D1 或回调错误。

### 12.3 模型与历史订单

- 模型和生产文件使用不可变版本；
- 发布新模型不改变旧订单；
- 无效模型阻止发布；
- 不允许用默认模型或默认文件伪装成功。

## 13. 测试与验收

### 13.1 自动测试

3D 交互：

- 正面不能命中被衣服遮挡的背面元素；
- 背面不能命中被衣服遮挡的正面元素；
- 45° 能命中真实可见元素；
- 候选元素被衣服遮挡时拒绝；
- 元素朝向错误时拒绝；
- 文字、号码和图片共用同一判断；
- 拖动不能穿透到另一面；
- 里侧不渲染外部图案；
- 旧设计文件继续读取。

导出：

- 完整 UV 包含模板、文字、号码和图片；
- 4096 Atlas 尺寸和颜色空间正确；
- PDF 页面、元数据和图像边界正确；
- manifest 与文件哈希匹配；
- ZIP 内容完整；
- 保存/重开/再导出结果保持一致。

订单与安全：

- 上传失败不创建可用购物车交接；
- 签名报价继续验证价格和组件；
- `orders/paid` HMAC 验证；
- 回调重复投递保持幂等；
- 订单行缺少或篡改 `designId` 时进入异常；
- 缺文件订单不能进入待生产；
- 未授权或过期下载链接被拒绝；
- 取消和退款状态正确更新。

### 13.2 真实浏览器与 Shopify 验收

- 桌面和移动端验证底纹面板已隐藏；
- 真实 WebGL 模型验证正面、背面、侧面、45°、领口和袖口；
- 每一种元素类型完成选择、拖动、旋转、缩放、复制和删除；
- 保存并重新打开设计；
- 下载并渲染 PDF，检查无裁切、模糊、错位或损坏；
- 在可安装 App 的测试店完成真实加入购物车、测试支付和订单回调；
- 从 Shopify 订单详情和 App 列表下载相同的生产 ZIP；
- 对生产 ZIP 执行 manifest 哈希校验。

## 14. 分阶段实施

### 阶段 1：顾客界面与 3D 交互安全

范围：

- 隐藏连续底纹高级参数；
- 修复摄像机可见元素选择；
- 修复元素里侧显示；
- 增加真实模型回归测试。

不做：

- PDF、R2、订单后台或模型上传。

完成标准：

- 第 13.1 节的 3D 自动测试通过；
- 桌面和移动真实浏览器验收通过。

回退：

- 回退独立前端提交与 Worker 静态资源版本。

### 阶段 2：完整生产文件

范围：

- 完整 UV 烘焙；
- 前后预览；
- UV 参考 PDF；
- manifest 与生产 ZIP。

不做：

- 云端订单关联和 1:1 工厂模板。

完成标准：

- 文件级自动测试和 PDF 可视化检查通过；
- 保存/重开/再导出一致。

回退：

- 保留原 design.json 导出；关闭新生产包入口。

### 阶段 3：云端暂存与订单关联

范围：

- R2、D1；
- 加购物车前上传；
- `orders/paid`；
- 草稿清理与正式订单状态。

不做：

- 完整模型管理 UI 和多店分发。

完成标准：

- 在可安装 App 的测试店完成测试支付闭环；
- 上传失败、重复回调和缺文件用例通过。

回退：

- 回退 Worker 版本；
- 禁用订单回调订阅；
- 保留已写入对象和索引，不做破坏性删除。

### 阶段 4：后台取件

范围：

- Shopify 订单详情 Admin Block；
- App 定制订单列表；
- 安全下载与状态管理。

完成标准：

- 两个入口都能按同一订单找到同一套文件；
- 权限、过期链接和异常状态通过。

回退：

- 关闭 Admin Block 或回退 App 版本；订单和文件仍保留。

### 阶段 5：模型管理与正式 App 入口

范围：

- GLB/纹理上传；
- 商品模型绑定；
- 模型验证和不可变版本；
- Theme App Extension / App Block；
- 替代脆弱的 Horizon DOM 启动方式。

完成标准：

- 新模型预览、发布、商品绑定和旧订单版本隔离通过；
- 未发布主题副本预览通过；
- 获得用户确认后才切换正式入口。

回退：

- 重新启用上一模型版本和上一 App Block 版本；
- Shopify 主题恢复到备份或上一预览验证版本。

### 阶段 6：多店可安装性验证

稳定运行后再执行：

- 移除单店硬编码配置；
- OAuth 和多店数据隔离；
- 安装、卸载和数据保留策略；
- 新店商品/变体/模型映射引导；
- 评估是否公开发布。

## 15. 版本与发布策略

- 实施使用独立 `codex/` 分支和隔离工作树；
- 当前工作区已有未提交改动，不得覆盖、暂存或混入提交；
- 每个阶段独立 commit、测试、构建和部署版本；
- Shopify live theme 修改前必须复制/备份；
- 主题改动先推未发布副本并使用预览链接验收；
- Worker 保留上一生产版本和回退记录；
- App、Functions、主题、Worker 与模型版本分别记录；
- 未经用户确认不发布主题、不切换 live theme、不影响真实支付。

## 16. 待实施前确认

进入实施计划前仍需在对应阶段确认：

- Cloudflare 账号是否可以开通并使用 R2、D1；
- 可用于安装自定义 App 和 Shopify Functions 的测试店；
- 正式商家店的安装权限与发布流程；
- 模型上传大小限制和允许的纹理格式；
- 顾客上传图片限制；
- 已付款生产文件的最终保留年限；
- 工厂何时可以提供 1:1 裁片模板。

这些事项不阻塞阶段 1 和阶段 2，但会阻塞阶段 3 以后正式上线。
