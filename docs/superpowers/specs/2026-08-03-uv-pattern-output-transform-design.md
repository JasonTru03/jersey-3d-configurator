# UV 裁片最终导出方向修正设计

日期：2026-08-03
基线：`438b05a`（UV 裁片生产图已发布）

## 目标

修正当前 `uv-pattern-pieces.png` 的最终落地方向：整张裁片图需要旋转 180°，旋转后其中的 `YOUR TEXT`、`PLAYER 16` 等文字仍为左右镜像，因此还需要水平镜像一次。

该修正必须是模型级生产导出参数，不能硬编码在通用导出逻辑中。后续替换 GLB 或重新整理 UV 后，如果模型本身已经正向，只需把旋转参数改为 `0`；如果文字也已经从左到右可读，再单独关闭水平镜像。

## 已确认的根因

当前正片和背片均配置为 `rotation: 180`、`mirrorX: true`。按现有“先旋转、再水平镜像”的裁片级变换规则，两者组合的实际效果等价于上下翻转。程序原有测试使用同一份配置计算期望采样点，因此只能证明配置被执行，不能独立证明导出文字在人眼看来正向可读。

用户提供的真实导出图给出了独立证据：

1. 原始裁片图的领口和文字上下颠倒；
2. 整图旋转 180° 后，裁片上下方向正确；
3. 旋转后的 `YOUR TEXT` 和 `PLAYER 16` 仍左右镜像；
4. 因此当前模型需要“最终整图旋转 180°，再水平镜像”。

## 范围

### 包含

- 在模型 UV 布局配置中增加最终裁片图变换参数；
- 当前 Chelsea 和 FN8788 布局显式配置旋转 180°和水平镜像；
- 裁片完成提取、转正和排版后，对最终 4096×4096 画布统一执行变换；
- 同步变换每个裁片的 `outputBounds`；
- 在裁片元数据、布局指纹和 `manifest.json` 中记录最终变换；
- PDF 第二页继续嵌入变换后的 `uv-pattern-pieces.png`；
- 增加独立方向标记测试和真实生产包视觉验收。

### 不包含

- 不修改实时 3D 模型预览方向；
- 不修改 `uv-atlas.png`，它必须继续保持 GLB 原始 UV 坐标；
- 不修改正面、背面预览 PNG；
- 不增加顾客可见的旋转或镜像控件；
- 不调整模型几何、UV seam、裁片分组或文字编辑交互；
- 不在本次改动中替换 GLB。

## 配置设计

在每个模型 UV 布局根级增加可选的 `patternOutputTransform`：

```js
patternOutputTransform: {
  rotation: 180,
  mirrorX: true,
  // 当前 GLB/UV 的生产裁片图需要先旋转 180°再水平镜像。
  // 后续模型若导出时已经朝上，将 rotation 改为 0；
  // 若文字也已经从左到右可读，将 mirrorX 改为 false。
},
```

规则：

- `rotation` 只允许 `0`、`90`、`180`、`270`；
- `mirrorX` 必须是布尔值；
- 变换顺序固定为先顺时针旋转，再对旋转后的结果水平镜像；
- 未配置时使用恒等变换 `{ rotation: 0, mirrorX: false }`，保证测试夹具和旧布局兼容；
- 正式支持的模型必须显式配置，避免换模型时隐式继承旧方向；
- 配置对象随布局一起冻结，运行时不得修改。

`pieceGroups[*].rotation` 和 `pieceGroups[*].mirrorX` 保持现有职责：它们只负责单片从原始 UV 中提取后的方向修正。`patternOutputTransform` 是独立的最终落地修正层，只执行一次，不替代单片参数。

## 导出流程

`createUvPatternPieces` 保持现有提取和排版流程，随后增加最终变换步骤：

1. 从真实 UV Atlas 提取每个裁片；
2. 应用裁片级 `rotation`、`mirrorX`；
3. 按固定留白排入临时 4096×4096 画布；
4. 将临时画布按 `patternOutputTransform.rotation` 旋转；
5. 对旋转结果按 `patternOutputTransform.mirrorX` 水平镜像；
6. 把最终像素写入生产裁片画布并编码 PNG；
7. 使用相同矩阵变换每个裁片矩形的四个角，重新计算最终 `outputBounds`；
8. 返回最终变换元数据并写入布局指纹。

当前画布是正方形，所以 90°或 270°不会改变 PNG 尺寸。变换必须使用离屏画布，禁止在已经写入的同一画布上覆盖读取，以免产生透明区域或像素污染。

## 元数据与生产包

裁片结果增加：

```js
outputTransform: {
  rotation: 180,
  mirrorX: true,
}
```

该字段进入：

- `uv-pattern-pieces.png` 对应的运行时元数据；
- `layoutFingerprint` 的稳定输入；
- `manifest.json` 的 `patternPieces.outputTransform`。

`manifest.json` 校验器必须拒绝无效角度、非布尔镜像值和缺失字段。正式生产包不允许元数据声称已变换但 PNG 仍是旧方向。PDF 第二页直接使用最终 PNG，因此无需增加第二套图像变换。

这是生产文件语义和 Manifest 必填字段的变更，因此同步把生产包 `schemaVersion`、模型 `uvExportVersion` 和 UV 布局 `version` 从 1 提升到 2。设计指纹会随版本变化，确保修正前后的 ZIP 不会得到相同文件名；旧设计文档本身仍按现有兼容逻辑读取。

## 测试与验收

### 测试先行

实现前先增加失败测试，覆盖：

- 模型布局参数被读取、冻结和校验；
- 默认恒等变换不改变现有测试夹具；
- 最终画布的四角像素在 0°、90°、180°、270°及镜像组合下落到正确位置；
- `outputBounds` 与最终像素位置一致；
- `outputTransform` 进入布局指纹和 Manifest；
- 无效角度和无效镜像值明确报错。

### 独立方向测试

新增一个不依赖配置反算期望值的不对称方向标记，例如左上、右上、左下使用不同颜色，同时放置可判定左右和上下的字形/数字标记。对当前模型固定断言最终结果为：

- 领口朝上；
- 标记上下方向正确；
- `PLAYER 16` 和普通文字从左到右可读；
- 正片和背片仍保持预期排版顺序；
- 胸前图案、姓名和号码均未被裁切。

这项测试不能再调用生产变换函数计算期望坐标，否则会重复原有的自证问题。

### 真实链路

- 运行相关单元测试、完整测试、应用构建、Showcase 构建和 Wrangler dry-run；

- 打开 `uv-pattern-pieces.png` 与 PDF 第二页，人工确认上下和左右方向；
- 未经新的明确确认，不推送远端或发布。

## 错误处理

- 配置角度不受支持时，模型 UV 布局校验失败并给出明确错误；
- `mirrorX` 不是布尔值时拒绝生成生产包；
- 最终画布创建或编码失败时，不回退为旧方向，也不生成不完整 ZIP；
- 变换后的裁片越界、为空或覆盖率异常时，沿用现有生产包失败策略。
