# 2026-08-12 多 Shopify 店铺订单后台

## 日期

2026-08-12

## 本次目标

把腾讯云独立订单后台由固定单店改造成安全的多 Shopify 店铺后台，允许工作人员登录后选择一个已配置店铺，查询该店铺订单并下载对应生产 ZIP。

## 修改范围

- 服务器配置读取与运行时校验。
- 后台会话、订单查询和 ZIP 下载接口。
- 后台店铺选择器、请求状态与响应式筛选布局。
- 配置、门户和 SQLite 运行时集成测试。
- 服务器示例环境变量与部署文档。

## 新增内容

- 从 `SHOPIFY_STORE_CONFIG_JSON` 生成有序、只读的 `adminShops` 白名单。
- 后台会话接口返回默认店铺和允许店铺列表。
- 后台筛选区增加 Shopify 店铺选择器。
- 查询与下载链接显式携带当前店铺。
- 增加跨店隔离、未知店铺拒绝和真实 SQLite 双店数据测试。
- 新增 `docs/superpowers/plans/2026-08-12-multi-shop-admin.md` 实施与回滚计划。

## 调整内容

- 保留 `ADMIN_SHOP` 作为默认店铺和会话签名范围，不破坏现有部署。
- 切换店铺时重置分页；通过请求序列避免较慢的旧店响应覆盖当前店铺结果。
- 筛选栏调整为六列桌面布局，沿用现有 900px 和 560px 响应式规则。

## 修复内容

- 修复后台只能查看 `ADMIN_SHOP`、无法查看同一服务器其他已配置店铺订单的问题。
- 阻止客户端通过伪造 `shop` 参数读取或下载白名单之外的店铺数据。

## 影响范围

- 无数据库 schema 变更，无 migration。
- 不修改 Shopify 订单、商品、支付、发货或客户数据。
- 尚未部署腾讯云，现有线上后台不受本地改动影响。

## 遗留问题

- 腾讯云仍运行旧单店版本，需单独批准备份、私有配置更新、镜像部署和容器重启。
- `#1001` 是否已由 webhook 写入数据库，要在部署多店版本后选择 `testcsj-secure-bundle.myshopify.com` 验证。
- 如果 `#1001` 从未收到 webhook，则需要确认订阅后再创建一笔新的测试订单；不得伪造已付款记录。
