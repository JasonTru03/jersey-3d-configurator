# Secure Jersey Shopify App

This directory contains the Shopify-side protection for the 3D jersey configurator:

- `secure-jersey-transform` verifies a signed component contract and merges the jersey plus surcharge into one cart line.
- `secure-jersey-validation` blocks altered, incomplete, underpriced, or quantity-modified custom bundles at cart and checkout.
- `scripts/configure-store.mjs` creates or updates both registrations and their app-owned configuration.
- `scripts/read-store-config.mjs` reads the registrations back without printing credentials.

## Store requirements

- A Shopify app-development store that permits custom app installation and Shopify Functions.
- One jersey product with exactly the configured `s`, `m`, `l`, and `xl` variants.
- One surcharge product whose variant prices cover every customization total generated by the configurator.
- The surcharge product should not be linked from storefront navigation or recommendations.
- Node.js 22.12 or newer, Shopify CLI, Wrangler, and the Rust toolchain pinned by `rust-toolchain.toml`.

A client-transfer store is not suitable for installing this custom app. Use an app-development store for testing and install the released app in each destination store.

## Credential handling

Keep every store-specific file under `shopify-app/local-config/`; this directory is ignored by Git.

Never paste an Admin token, Shopify API secret, or cart quote signing secret into tracked files, command output, screenshots, or documentation. When uploading a Worker secret on Windows, redirect an exact UTF-8 file without a trailing newline instead of piping PowerShell text:

```powershell
cmd /c "npx wrangler secret put CART_QUOTE_SIGNING_SECRET < shopify-app\local-config\cart-quote-signing-secret.txt"
cmd /c "npx wrangler secret put SHOPIFY_API_SECRET < shopify-app\local-config\shopify-api-secret.txt"
```

The same signing-secret bytes must be used by the Worker and both Shopify Function registration metafields.

## Installation sequence for another store

1. Copy the jersey and surcharge products to the destination store and record the numeric product/variant IDs.
2. Create or select the destination Shopify app, configure the App Proxy path as `/apps/jersey-configurator`, and set its proxy URL to the Worker handoff endpoint.
3. Create a local Shopify CLI configuration for that app/store. Do not commit the generated configuration or `.shopify/` session files.
4. Install dependencies and verify the source:

   ```powershell
   npm ci
   npm test
   npm run build
   ```

5. Release both Functions with the app:

   ```powershell
   npm run deploy:check
   npm run deploy
   ```

6. Create `local-config/STORE-install.json` with this exact structure. Replace every placeholder and keep variant IDs as strings:

   ```json
   {
     "shop": "STORE.myshopify.com",
     "adminAccessToken": "ADMIN_TOKEN",
     "storeConfig": {
       "schema": 1,
       "shopFingerprint": "SHOP_FINGERPRINT",
       "signingSecret": "SIGNING_SECRET",
       "productId": "fn8788-jersey",
       "currency": "USD",
       "jerseyVariants": {
         "s": "VARIANT_S",
         "m": "VARIANT_M",
         "l": "VARIANT_L",
         "xl": "VARIANT_XL"
       },
       "surchargeVariants": {
         "8": "SURCHARGE_VARIANT_8",
         "18": "SURCHARGE_VARIANT_18"
       }
     }
   }
   ```

   Include every surcharge amount the pricing engine can generate. The `shopFingerprint` is deterministic for the lowercase `*.myshopify.com` domain; use the project helper or a redacted dry-run to obtain it.

7. Preview the registration plan, apply it, then read it back:

   ```powershell
   npm run configure:store -- --config local-config/STORE-install.json --dry-run
   npm run configure:store -- --config local-config/STORE-install.json --apply
   npm run read:store-config -- --config local-config/STORE-install.json
   ```

8. Add the same store mapping to the Worker configuration, upload both Worker secrets from exact files, and deploy with `npx wrangler deploy`.
9. Configure the product launcher so buyers enter the 3D configurator instead of adding the raw jersey directly.
10. Run the acceptance checklist below before enabling sales.

## Required acceptance checklist

- Normal customization creates one merged jersey line whose price equals the server quote.
- The handoff page redirects to `/cart` once; refreshing or revisiting does not duplicate the bundle.
- Removing the surcharge component directly is rejected and the cart remains unchanged.
- Increasing the merged quantity is rejected and the cart remains unchanged.
- Replacing the signed surcharge with a cheaper surcharge variant is rejected and the cart remains unchanged.
- Removing the merged parent deletes the complete bundle.
- A valid merged bundle reaches Shopify checkout without a validation error.
- Fulfillment resolves the trusted `designId`; buyer-facing summary text is never treated as authorization or pricing proof.

## Rollback

Before changing a live store, save redacted registration IDs, owner-metafield digests, Worker version, product mappings, and theme launcher assets. To roll back, restore the previous Worker version and store mapping, then deactivate/delete the test registrations or restore their previous app-owned metafields. Never delete or replace live registrations until the rollback snapshot has been verified.
